---
title: On an nginx publication host, the media map is now pushed by Apply media rules, and shared safely by every instance on the host.
type: added
audience: admin
date: 2026-10-08
---
nginx's media rules need a small map in the server's `http {}` block (it checks the media login cookie and decides how SVG files are served). That map may be defined only once per server, but a publication host can carry several Dédalo instances, and until now it had to be placed and kept current by hand. On a publication host whose declaration sets `web.nginx_map: conf_d`, **Apply media rules** now sends this work system's map to the agent before the media rules. The agent never writes the file nginx loads: it hands its part to a small service that runs as root on the host, which checks every instance's part, merges them into one file, tests the configuration and reloads nginx. When every instance runs the same Dédalo version and media folder, the file is exactly the map Dédalo writes for a work host. The publication hosts panel shows the map's state for each host: the map expected and the map applied, the shared host map and how many instances it serves; a host whose map is out of date counts as drift. The host refuses, and the panel says why: a map that is not in the expected form, an instance whose media folders changed since its map was first accepted (the earlier map stays until `provision apply` is run for that instance), or another instance with a newer map than the host's renderer understands (the shared map is left as it is until `provision apply` is run for that newer instance). `provision init` sets `web.nginx_map: conf_d` when nginx includes `conf.d` inside `http {}` (the Debian and RHEL default), and moves a map placed earlier by hand into the shared one after you confirm. A host whose map is placed by hand (`web.nginx_map: none`, the default of a hand-written declaration) is not touched, and an agent too old to know the shared map is refused with a request to update it. Every configuration test and reload on a publication host, by the agent or by root, now waits for the others, so two instances can no longer reload the same web server at the same time; if the shared lock is missing, run `provision apply` for the instance.
