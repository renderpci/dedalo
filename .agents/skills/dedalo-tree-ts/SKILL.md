# Dédalo v7 tree (TypeScript rewrite)

Two areas — `area_thesaurus` (thesauri, main section `hierarchy1`) and `area_ontology` (the ontology source-of-truth, main section `ontology35`, a virtual section of hierarchy1) — render hierarchy sections as an interactive tree via ONE machinery. They differ only in which main section + main table they read; `dedalo-ontology-ts` owns the definitions the tree displays. The frozen PHP tree (`v7_php_frozen/master_dedalo`, outside the repo) is historical reference for how behaviour was ported — never an oracle; read-path parity replays the frozen fixture store. Never silently narrow; throw + ledger the gap in the file header.

**Storage inversion (never change):** the CHILD stores its parent locator (type `dd47`) in its `relation` column under the `component_relation_parent` tipo. Children are ALWAYS computed by searching who points at the parent; there are no stored children rows (`component_relation_children` `use_db_data=false`). Sibling order is a per-parent `id_key` dataframe on the child's order component_number (id_key = the parent-link locator's item id), NOT an array index.

**Node identity:** `ts_id = "${section_tipo}_${section_id}"`, `ts_parent` likewise, `'root'` for area-attached roots.

## Shared foundation (also used by dedalo-ontology-ts)
`src/core/db/postgres.ts`:
- `withTransaction(work)` — AsyncLocalStorage ambient transaction via a Proxy over the pool. Every `sql` call inside (directly or in any awaited helper) routes to ONE reserved connection, so in-tx reads see in-tx writes like PHP's per-request connection. A throw rolls back. Nesting JOINS the ambient tx (no nested BEGIN).
- `acquireNodeLock(sectionTipo, sectionId)` — `pg_advisory_xact_lock(hashtext('<tipo>_<id>'))` (the key PHP `matrix_db_manager::acquire_node_lock` used — any second client locking the same key serializes). Throws outside a tx.
- `src/core/ontology/tld.ts` (safeTld `/^[a-z]{2,}$/`, getTldFromTipo, getSectionIdFromTipo, mapTldToTargetSectionTipo=`tld+'0'`, buildTipo, isMainTipo), `ontology_tipos.ts` (all constants — dd47/dd48/dd96/dd64, HIERARCHY_*/ONTOLOGY_*), `cache_invalidation.ts` (zero-import registry hub; register your caches, ontology writes fan out to them).

## Architecture — `src/core/ts_object/`

`src/core/relations/children.ts` gained `countChildrenOrNull` (null when unresolvable ≠ 0), `getComponentOrderTipo`, `getChildrenOfType` (descriptor filter). `src/core/search/search_related.ts` `countInverseReferences({groupBy})` = PHP `count_data_group_by` (indexation icon). `dispatch.ts` only registers `dd_ts_api` (`tsApiActions`); the 5 thin wrappers live in `src/core/api/handlers/dd_ts_api.ts` and build envelope v2 (`ok(data)`, non-fatal findings as the `errors` extension key); a refusal THROWS a `DedaloError` from `ts_api.ts` and rides the dispatch catch with its registry status (the PHP always-200 `result:false` parity is repealed). The area_thesaurus/area_ontology serving lives in `src/core/area/` — `tree.ts` builds the boot payload (roots + typologies + terms_are_model; formerly resolve/area_hierarchy.ts, relocated by the area-module refactor, byte-parity preserved) and `read.ts` (`dispatchAreaRead`) applies the per-hierarchy perms filter (ontology+admin bypass) and the ts_search injection.

## Batch-first, no legacy fallback
PHP's ts_node_repository returns null→legacy per-component path; TS has no such path (both yield identical values), so: missing row → `{order:null, is_indexable:false}`; missing descriptor flag → null-skip; bad tipo grammar / SQL error → THROW. The one observable fallback (`count_children===null` → load-and-count) is preserved via `countChildrenOrNull`.

## PHP node-builder semantics (each an explicit test)
- Element types from the `section_list_thesaurus` child's `properties.show.ddo_map`: term | icon | link_children | link_children_model. model-mode: `model=true` drops link_children for hierarchy1/ontology35 roots, promotes link_children_model→link_children; `model=false` drops link_children_model.
- **Icon component data must be resolved in the ELEMENT LANG** before the empty-skip: `translatable ? DEDALO_DATA_LANG : 'lg-nolan'` (PHP `common::get_element_lang`). Getting this wrong leaks icons (e.g. an `OB` icon on a non-translatable text_area that is empty in its element lang).
- icon `CH` always skipped; icon `ND` → `is_descriptor=false` when first item `(int)section_id===2`, icon itself not rendered; `component_relation_index` icon → `"ICON:total"` + count_result (totals_group field is `value` not `count`), zero-total → element suppressed; other empty icons skipped.
- icon `M` → also stamps `model_value` (PHP `class.ts_object.php:518` `$component->get_value()`), the orange model badge area_ontology toggles with **Ctrl+M**. Gated on the RESOLVED value `'M'`, never the ddo `icon` key (so `component_relation_index`'s `"M:3"` cannot match). Resolution deliberately BYPASSES the target's `thesaurus` term scope (which yields the bare tld for a model record): raw locators off the record → the component's OWN `properties.source.request_config[].show.ddo_map` (`section_tipo:'self'`) tipos → `getDdoValueByLocator` with the WIDER grid fallback (data-lang → main → lg-nolan → any, translatable only — model names live in ONE lang, so a strict read empties every badge). Two live sites: `ontology6` (ontology tree), `hierarchy27` (hierarchies tree).
- link_children → `children_tipo`, `has_descriptor_children` (batchDescriptorFlags), synthetic `{type:'link_children_nd'}` when ND children exist. Non-descriptor rule: `is_descriptor===false && type==='link_children'` → children_tipo=null, skip.
- `isIndexable`: hierarchy/ontology root tipos always false; else first locator `section_id===1`.
- Permissions: hierarchy1 button_new→hierarchy11, button_delete→ALWAYS 0 (roots undeletable); hierarchy20 → hierarchy38/hierarchy39.
- `parseChildData` assumes HOMOGENEOUS children (order tipo from FIRST locator); it is now the section_id CANONICALIZATION BOUNDARY (WC-2026-08-10-section-id-int-canonical: `canonicalizeStoredSectionId` + `isSectionId`, non-addresses skipped) — downstream ts_object code takes plain `number`; dedup/prefetch keys use `${tipo}_${int(id)}`. dd_ts_api RQO-body ids coerce at the door via `coerceSectionId` (`rqo.dd_ts_api.<action>.<field>` counters).
- `pickOrderValueForParent` priority: id-keyed match (`item.id_key ?? item.id` — the written pairing field is `id`; `{value,id}` is what add_value_by_id_key/addInlineValueByIdKey produce) → section_tipo_key+section_id_key → truly unkeyed (no pairing key of ANY generation) → first. **WC-015**: PHP's picker matches the phantom `$item->id_key` and returns the FIRST item's stale value on multi-item dataframes (multi-parent/moved nodes) — the reorder-reverts-on-reload bug; TS deliberately diverges. The client sorts children by this `order` field (`ts_object.js`), so a wrong pick visually reorders the tree. Gate: ts_tree_semantics 1b–1d.

## dd_ts_api (wire contract)
Envelope v2 (see **`dedalo-errors-ts`** — `result` is a forbidden key); refusals are `DedaloError`s whose `publicMessage` keeps the PHP-era msg strings. `get_node_data`/`get_children_data`: read gate ≥1. Mutations: write gate ≥2, PRE-validate before any write (no orphan window), then `withTransaction` + `acquireNodeLock`:
- `add_child`: lock parent → createSectionRecord → save is_descriptor+is_indexable defaults (dd64/1) → TLD ontology7 inheritance when `getSectionIdFromTipo(section_tipo)==='0'` → addParent(type dd47). Result = int new_section_id.
- `update_parent_data`: cycle guard (self-target OR isAncestor → throws `DedaloError('tree.cycle')`) BEFORE mutating → lock BOTH parents strcmp-sorted → removeParent(old) → addParent(new) → recalculateSiblingOrders(old).
- `save_order`: lock parent → sortChildren → `syncOrderToDdOntology(changed, parentTipo, parentId)` (dynamic-imported from `src/core/ontology/ontology_write.ts`, Track B); `sortChildren` answering `false` (section_map declares no `order` component) throws `DedaloError('resource.conflict')`, nothing written.
Cache invalidation runs only AFTER commit; mutation handlers never populate read caches (so rollback needs no cache clear — TS has no per-request instance caches).

## Tree search (searchThesaurus)
SQO → hits → per hit `getParentsRecursive` (memo BY REF, visited BY VALUE → diamond-DAG safe) → reverse top-down. For each ancestor: emit FULL sibling set FIRST (positional order index+1, mode 'list') THEN the ancestor node (order null for non-root; `getMainOrder(tld)` for root). Dedup keeps FIRST occurrence per `section_tipo:section_id` — match PHP's iteration so the same occurrence wins. `getMainOrder` reads `matrix_ontology_main` (PHP `hierarchy extends ontology` → get_main_order reads the ONTOLOGY main, NOT matrix_hierarchy_main) → null when no ontology main (thesaurus TLDs). `getHierarchyTermsSqo`: preserves PHP's shared-`$path` mutation quirk (parity over "fixing").

## Gotchas
- Caches (term, resolved-child) are keyed by CONTENT only (tipo/id/scope/lang — NEVER user/session): persistent-runtime discipline. Register clearers with the hub.
- `removeInlineByIdKey`/`updateInlineValueByIdKey` (relations/dataframe.ts) are the pure id_key contract backing order machinery.
- `insertMatrixRecordWithExplicitId` (advisory-locked, raises counter, throws on dup) + `createSectionRecord(...,sectionId?)` for deterministic node ids.

## Testing
Tests build their situation on the suite DB (`bun run test:db:setup`, `dedalo_test_marker`) with the generic `test` TLD — see **`dedalo-ts-testing`**. Unit: `test/unit/{tld,with_transaction,node_lock_coexistence,ts_tree_semantics,ts_tree_db_semantics,ts_search_native}.test.ts`. Parity: `test/parity/ts_{node_read,search}_differential.test.ts` replay the frozen fixture store in `test`-TLD terms (`testimmovable1`, the clone of the old tchi1 fixture; children tipo `testimmovable1038`); `ts_mutations_differential.test.ts` + `ts_mutations_hardening.test.ts` (concurrency: 2 racing add_child → distinct ids + distinct sibling orders) are `NO_ORACLE_GATES` — every record they assert on is one they wrote. A red frozen-fixture gate or a fixture/WC edit → **`dedalo-parity-debugging`**. The `model_value` gate (`ts_tree_db_semantics`) uses the core ontology (`dd0/35`→`area_tool`, asserted in 3 langs). Client side: `client/dedalo/test/client/js/test_ts_object.js` "Model badge" (badge text + the `hide`/`show_models` toggle), run via `bun run test:client`. Write tests self-revert (create→read-back→delete); NEVER leave scratch records.
